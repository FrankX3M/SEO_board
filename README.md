# Автотесты техаудита — фундамент (прод)

Проверяется **прод**. Препрода и куки больше нет. Готово: единые настройки доступа, справочники
страниц по сетям, сбор HTML (raw + rendered), пробы (редиректы, 404, robots.txt, карты сайта,
favicon/манифест/og:image) и хранилище (файлы + SQLite). Проверки чек-листа и отчёты (Excel + HTML) — модуль `techaudit/checks`, запуск `run_checks.py` (см. раздел ниже).

## Quick start

Windows, из папки проекта (один раз — шаги 1–2, дальше только 3–6):

```
:: 1. окружение
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
playwright install chromium

:: 2. настройки: запустите веб-интерфейс и заполните «Доступ» → Сети (адрес, токен, карты сайта; токен у каждой сети свой)
python web.py
:: (.env не обязателен; если он уже есть — кнопка «Перенести из .env» на той же странице)

:: 3. самопроверка кода (сайт не трогает, ~15 с)
python -m unittest tests.test_checks tests.test_smoke

:: 4. план без запросов: видно сети, UA, наличие токена (значения не выводятся)
python collect_html.py --dry-run

:: 5. пробный сбор: 2 страницы на тип + все пробы
python collect_html.py --network 5ka --limit 2 --probes all

:: 6. проверки чек-листа + живая выборка → отчёты в data\reports\
python run_checks.py --live

:: 7. (необязательно) ИИ-этап: сводка, первопричины, черновики задач и комментариев. Ключ ИИ задаётся в «Доступ → ИИ-анализ»
python run_checks.py --ai
```

Результат шага 6: `data\reports\<запуск>-checks.html` (открыть в браузере) и `<запуск>-checklist.xlsx` (копия чек-листа с результатами).
Исходный чек-лист не меняется. Полный сбор — без `--limit`; повторный пересчёт проверок без запросов к сайту — `python run_checks.py`
(без `--live`). Если что-то пошло не так, первым делом смотрите вывод шага 4 и статусы «Пропущено» в отчёте: в них написано, чего не хватает.

## Установка (Windows) — подробно

```
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
playwright install chromium
python web.py
```
**Настройки задаются в веб-интерфейсе** (страница «Доступ»), `.env` не нужен. Сети, токены, User-Agent, пути к sitemap, ключи
внешних сервисов и пороги хранятся в БД (`data/techaudit.db`); консольные скрипты (`collect_html.py`, `run_checks.py`,
`import_crawl.py`, `compare_html.py`), расписание и запуски из интерфейса читают те же значения: при старте они подставляются в
окружение поверх `.env`. Изменения в интерфейсе действуют сразу, перезапуск не нужен. Добавить свой проект — «Доступ → Сети → Добавить сеть»
(ключ, адрес, токен, карты сайта); сеть сразу появляется в справочнике страниц, дальше добавьте её URL.

**`.env` — необязательный запасной вариант.** Всё, что не задано в интерфейсе, берётся из него (поиск: `--env-file <путь>` →
`TECHAUDIT_ENV` → `.env` выше проекта → `.env` в проекте), поэтому старая настройка продолжает работать. Кнопка
«Перенести из .env» копирует сети и значения в БД; после этого файл можно удалить. Если в БД есть хотя бы одна сеть, список сетей
берётся только из БД. Секреты в интерфейсе, логах и записях запусков не показываются (пустое поле = «не менять»); БД лежит в `data/`,
которая исключена из git — не публикуйте её и не отправляйте вместе с проектом.

**Карты сайта (sitemap).** Пути к sitemap могут отличаться от указанных в `robots.txt` или не упоминаться там вовсе, поэтому для каждой
сети в интерфейсе задаётся свой список (полный URL или путь от адреса сети, по одному в строке). Пробы собирают карты из `robots.txt`
(можно отключить), из этого списка и, если ничего не нашлось, из `/sitemap.xml` (можно отключить); индексные карты раскрываются
на два уровня. Кнопка «Проверить карты сайта» в карточке сети сразу показывает статус, тип, число URL и ошибки без полного сбора.

## Правила доступа

- **Токен сайта обязателен** для всех запросов (он обходит антифрод) и **у каждой сети свой**: задаётся в карточке сети
  («Доступ → Сети», при необходимости свой заголовок токена; в `.env` это `NET_<СЕТЬ>_TOKEN`). Общий токен
  оставлен только запасным вариантом, и скрипт предупредит, что для сети используется он.
  Нет токена сети — скрипт не стартует и к сайту не ходит. Выключить можно только явно, для диагностики:
  `--no-token` или настройка «Отправлять токен» = нет.
- Токен сети уходит только на хосты этой сети (не на счётчики, CDN и другие сети) и никогда не пишется в БД и логи.
  Пробы `http → https` идут по http, поэтому токен уходит и туда: это ваш хост, но имейте в виду.
- UA: «UA для бота» (поисковик, по умолчанию googlebot) — для вариантов `bot`/`browser`;
  «UA обычного клиента» (desktop) — для `plain` и проб. Свои профили добавляются в «Доступ → Профили UA».
  Переопределяется флагами `--ua`, `--plain-ua`.
- **Внешние сервисы** (PageSpeed, Search Console, Вебмастер, key.so) необязательны. Нет ключа в настройках —
  связанная проверка получит статус «пропущено», скрипт не падает (`techaudit/integrations.py`:
  `guarded()` превращает и отсутствие ключа, и сбой сервиса в статус, а не в исключение).

## Справочник

`registry/<ключ_сети>.csv`, колонки `type,url,note`. **Адрес из справочника считается правильным
(канонической формой)**: пишите его в нижнем регистре и с тем слешем, как должен отдаваться сайт.
Пробы строят искажённые варианты от него. Хост подставляется из `NET_<СЕТЬ>_URL`.
Пример — `registry/5ka.csv`, шаблон — `registry/_template.csv`.

## Варианты страницы и сравнение «до / после рендеринга»

| вариант | как получен | что показывает |
|---|---|---|
| `plain` | сырой HTML, обычный UA | страница без рендеринга |
| `bot` | сырой HTML, UA поисковика | что сервер отдаёт боту (рендеринг на стороне сервера) |
| `browser` | Chromium, UA поисковика | то, что остаётся дорисовать JS поверх HTML бота |
| `browser-plain` | Chromium, обычный UA | страница глазами пользователя (по запросу) |

По умолчанию `plain,bot,browser`, сравниваются соседние пары. Блок определяется по `data-qa` / `id` /
семантическим тегам, номера схлопываются (`product-card-4280098` → `product-card-*`). Отчёт:
`data/reports/<запуск>-diff.html`. Пересчёт без запросов к сайту: `python compare_html.py [--run … --pairs …]`.

## Пробы (чек-лист: редиректы, коды ответа, sitemap, favicon…)

Для каждого URL из справочника (не более `PROBE_LIMIT` каждого типа, по умолчанию 2) строятся искажения;
сайт должен вернуть **один 301** на правильный адрес:

| проба | что запрашиваем | пункты чек-листа |
|---|---|---|
| `slash` | слеш в конце меняется на противоположный | 1 |
| `upper` | путь ЗАГЛАВНЫМИ | 2 |
| `alt_host` | с www ↔ без www | 3 |
| `http` | `http://` вместо `https://` | 4 |
| `combined` | http + другой хост + заглавные + слеш сразу | 5 |
| `index_php`, `index_html` | `/…/index.php`, `/…/index.html` (кроме типов из `PROBE_INDEX_SKIP`) | 6 |
| `not_found` | в URL заменён последний сегмент на несуществующий слаг: нужен прямой 404, без редиректа; тело сохраняется для проверки шаблона | 8, 10, 11 |
| `robots`, `sitemap` | `/robots.txt`, адреса карт из него (запасной `/sitemap.xml`), вложенные карты, число URL, лимиты | 44–49 |
| `favicon`, `apple_icon`, `manifest`, `manifest_icon`, `og_image` | ресурсы из `<head>` страниц + `/favicon.ico`: статус, тип содержимого, размеры картинок, JSON манифеста и его иконки | 61, 64 |

Каждая проба получает вердикт `pass`/`fail` и причины (`not_301:302`, `multi_hop:2`, `wrong_target`,
`no_redirect_200_duplicate`, `redirected:302`, `status_404`…) — таблица `probes` в БД и сводка в конце прогона.
`NET_<СЕТЬ>_URL` задаёт «правильный» хост: если сайт должен быть на www, укажите его с www.

```
python collect_html.py --probes redirects              # только редиректы
python collect_html.py --probes not_found,discovery    # 404 + robots/sitemap
python collect_html.py --probes-only --probe-limit 5   # без страниц, больше URL на тип
python collect_html.py --no-probes                     # только страницы
```

## Запуск

```
python collect_html.py --dry-run                       # план, доступы, внешние ключи — без запросов
python collect_html.py --network 5ka --limit 2         # быстрый пробный прогон
python collect_html.py --variants plain,bot            # без браузера
python collect_html.py --network 5ka --url /catalog/   # разовый URL вместо справочника
python collect_html.py --ua yandexbot                  # другой UA поисковика
python collect_html.py --no-token                      # диагностика: что отвечает сайт без токена
```

## Что сохраняется

```
data/html/<запуск>/<сеть>/<тип>/<slug>.<вариант>.html   # plain, bot — байты ответа как есть;
                                                       # browser* — DOM после JS, в начале SOURCE_URL / SAVED_AT
data/html/<запуск>/<сеть>/_probes/<вид>/…              # тела 404, robots.txt, карты, манифест
data/techaudit.db                                      # runs, pages, diffs, probes
data/reports/<запуск>-diff.html                        # отчёт сравнения вариантов
```
Файлы `plain`/`bot` без комментариев в начале: проверка charset смотрит первые 1024 байта документа.

## Самопроверка

```
python -m unittest tests.test_smoke -v
```
Мок-сайт с токеном: статусы, цепочки редиректов, переключатели доступа, отсутствие секретов в БД,
обязательность токена, пропуск проверок без внешних ключей, все виды проб и разница raw/rendered.

## Проверки чек-листа и отчёты (`run_checks.py`)

Порядок работы: **собрать данные → прогнать проверки → открыть отчёты.**

```
python collect_html.py --probes all                  # страницы + пробы (редиректы, 404, robots/sitemap, favicon/OG-картинки)
python run_checks.py                                 # проверки по последнему запуску → Excel + HTML в data/reports/
python run_checks.py --live                          # + выборка ссылок/картинок/canonical/sitemap/utm/?page=2 с прода
python run_checks.py --list                          # какой пункт чек-листа какой проверкой закрыт
python run_checks.py --only viewport,canonical_present --no-xlsx
python run_checks.py --baseline <run_id>             # эталон текущего прода: «сохранён формат json-ld + микроданные»
python run_checks.py --mobile-run <run_id>           # запуск collect_html.py --ua googlebot-mobile --variants bot
```

Сопоставление с чек-листом идёт **по названию пункта** (подстрока, `techaudit/checks/c_*.py`, декоратор `@check`), поэтому
порядок строк в Excel не важен. Файл чек-листа: `--checklist`, переменная `CHECKLIST_XLSX` или поиск `*тсх*.xlsx` рядом с проектом.
Исходный Excel **не изменяется**: рядом с отчётом создаётся копия `<запуск>-checklist.xlsx` с колонками «Автопроверка: итог»,
«<сеть>: статус / результат», листами «Автопроверка - сводка» и «Автопроверка - детали» (все URL, не прошедшие проверку).
HTML-отчёт — `<запуск>-checks.html` (вкладки по сетям, фильтр по статусу, критичные провалы сверху, детали по URL).

Статусы: **Пройдено / Требует внимания** (прошло, но есть оговорка или нужна ручная сверка) / **Не пройдено** / **Пропущено** (нет проб,
ключа внешнего сервиса, краула или это ручной пункт — в тексте сказано, что именно запустить) / **Нет данных** (в справочнике нет страниц нужного типа).

| группа | откуда данные | что нужно запустить |
|---|---|---|
| редиректы, 404, sitemap, favicon/OG-картинки | таблица `probes` | `collect_html.py --probes all` |
| HTML: canonical, robots, OG, Twitter, viewport, charset, lang, alt, крошки, меню/футер, микроразметка, TTFB | `pages` + файлы HTML | обычный `collect_html.py` (для «динамических блоков» — вариант `browser`) |
| ссылки на редиректы/404, битые картинки, цели canonical, URL из sitemap, canonical с `?utm`/`?page=2` | таблица `live_urls` | `run_checks.py --live` (токен и UA из `.env`; не краул, выборка `LIVE_LIMIT`) |
| GSC, Яндекс Вебмастер, PageSpeed (мобилопригодность, CWV) | внешние сервисы | ключи в `.env`; без них — «Пропущено». Клиенты API пока не подключены |
| страницы-сироты, ручные пункты (кеш карт) | полный краул / человек | в модуле не реализовано, статус «Пропущено» |

**Роли страниц.** Тип из справочника (`type`) сводится к роли (`home`, `product`, `listing`, `search`, `filter`, `info`) по шаблонам в
`checks/core.py::ROLE_PATTERNS`; исключения — `ROLE_OVERRIDES=тип:роль,…` в `.env`. Для страниц роли `search` (и URL с `sort=`, корзина, ЛК)
`noindex` считается правильным, а не ошибкой. Разводящие типы (`NAV_TYPES`, по умолчанию `catalog,cat_l1`) не обязаны содержать товары.

**Как добавить проверку:** функция `def my_check(ctx) -> Result` в `techaudit/checks/c_*.py` с декоратором
`@check("id", "подстрока названия пункта")`. `ctx.primary()` — страницы для бота, `ctx.pages(variant)`, `ctx.probes(kind)`,
`ctx.live(kind)`, `ctx.sitemap`; результат собирается через `from_items(...)`. Пункт без совпадения в чек-листе остаётся ручным.

Ограничения: проверки работают по **выборке страниц справочника**, а не по краулу (в итогах это указано). Rich Results Test и валидатор
Яндекса не подключены: «Валидация разметки» проверяется локально (JSON-LD, обязательные поля) и получает «Требует внимания».

Самопроверка: `python -m unittest tests.test_checks tests.test_checks_extra -v` (синтетические страницы + сквозной прогон на мок-сайте).

### Дополнительные проверки (нет в Excel-чек-листе)

Кроме пунктов чек-листа считаются 37 дополнительных проверок (`techaudit/checks/x_*.py`, декоратор `@xcheck` из `extras.py`).
В отчёты они попадают отдельными блоками **после** строк чек-листа (в Excel — дописываются ниже исходных строк, исходные ячейки не меняются):

| блок | проверки |
|---|---|
| Индексация и дубли | дубли title / description / H1 (по краулу Screaming Frog, если выгружен, иначе по выборке), дубли основного текста, цепочки и циклы canonical, canonical в заголовке `Link` против HTML, адреса sitemap против canonical, hreflang, «мягкие» 404, страницы с noindex, закрытые в robots.txt |
| Мета-теги и заголовки | заглушки (`title`, `metaDescription`, `undefined`, `{{ }}`), длина и наличие title / description, один H1, структура H2–H6 |
| Robots.txt и Яндекс | валидность robots.txt, доступ Googlebot и YandexBot к страницам, CSS/JS и URL из sitemap, Clean-param, доступ ИИ-ботов, `llms.txt` |
| URL и ссылки | единый вид внутренних ссылок (регистр, `//`, utm, http, слеш), смешанный контент, чистота sitemap (повторы, undefined, чужие хосты), тестовые копии (`/crm-test/`), анкоры «подробнее», глубина страниц по краулу |
| Сервер и заголовки | сжатие, `Cache-Control` (синтаксис), `Vary: User-Agent`, одинаковые мета для бота и пользователя, ETag / Last-Modified и 304, HSTS и другие заголовки, TLS-сертификат основного и второго (www) хоста |
| Производительность HTML | вес HTML и размер DOM, блокирующие скрипты в head, картинки (width/height, lazy, webp) |

Данные берутся из тех же источников, что и остальные проверки: страницы и пробы (`collect_html.py --probes all`), живая выборка
(`run_checks.py --live`: теперь ещё TLS-сертификат, `/llms.txt` и условные запросы для проверки 304), краул Screaming Frog (раздел «Краул»).
Без нужных данных проверка получает «Пропущено» с подсказкой. Пороги — в `.env` (`TITLE_MAX`, `DESC_MAX`, `MAX_DEPTH`, `HTML_WARN_KB`, `DOM_WARN`,
`CERT_MIN_DAYS` и др., см. `.env.example`). Свою проверку без пункта в Excel добавляйте через `@xcheck(id, блок, название, критерий, приоритет)`.

### План работ: приоритет, роль, часы

К каждой проверке (и из Excel, и дополнительной) в отчётах добавляются приоритет, роль, оценка в часах, ожидаемый результат и волна
(`techaudit/checks/plan.py`). В Excel — колонки справа и лист **«План работ»** (задачи по непрошедшим пунктам, итоги по ролям), в HTML — раздел
«План работ» и колонка «Роль · часы», в веб-интерфейсе — роль и часы рядом с приоритетом.

- Приоритет берётся из Excel; пустое значение или шаблон вроде `{{USERNAME}}` заменяется значением по умолчанию (`DEFAULT_PRIORITY`) или «Средний», исходное значение сохраняется.
- Часы — оценка на исправление при статусе «Не пройдено»; «Требует внимания» считается как `PLAN_WARN_SHARE` (0,5) от оценки; пройденные пункты — 0.
- Часы заданы на сеть как одну задачу (общая платформа); если сети правятся независимо — `PLAN_PER_NETWORK=1`.
- Свои роли и часы: CSV в `PLAN_FILE` (колонки `check_id;role;hours;result`). Роли: `DEV`, `DEVOPS`, `SEO`, `PM`, `CONTENT`.
- Волна по приоритету: Критично → 1, Высокий → 2, Средний → 3, Низкий → 4.

## ИИ-этап (`run_checks.py --ai`)

Корпоративный OpenAI-совместимый API (`AI_API_URL`, по умолчанию `https://api-copilot.x5.ru/v1`; ключ `AI_API_KEY`, модель `AI_MODEL`,
по умолчанию `x5-airun-medium`). Быстрая проверка ключа и модели:

```
curl https://api-copilot.x5.ru/v1/models/ -H "Authorization: Bearer <ключ>"
python run_checks.py --ai --only viewport --no-xlsx      # минимальный прогон с ИИ
```

Что делает: **(1)** по результатам «не пройдено / требует внимания» пишет сводку для руководителя, первопричины («одна правка закрывает
несколько пунктов»), черновики задач для трекера и черновик текста в колонку «Комментарий»; **(2)** смотрит фрагменты страниц и отвечает,
есть ли видимое текстовое описание и не скрыто ли оно (пункт, где эвристика даёт только «Требует внимания»).

Правила: ИИ **не меняет статусы** проверок; всё помечено «черновик / вывод ИИ». В запрос уходят результаты проверок и фрагменты
текста (≤ 500 симв. на блок), токен сайта и заголовки ответов — нет. Ответы кешируются по хешу (таблица `ai_cache`), повторный запуск
не тратит запросы; лимит — `AI_MAX_REQUESTS`. Нет ключа или сбой API — этап пропускается, отчёты строятся без него. Результат: блок
«Сводка ИИ» в HTML, колонка «ИИ: черновик комментария» и лист «ИИ - сводка» в Excel.

## Веб-интерфейс

```
pip install -r requirements.txt
python web.py                 :: http://localhost:8765 (открывается сам; --no-open, --port, --env-file)
python -m unittest tests.test_web
```
Слушает только локальный адрес, входа нет (`--allow-remote` — на свой риск). Токены, UA, карты сайта, ключи и пороги задаются на странице «Доступ» и хранятся в БД
(те же значения читают консольные скрипты); секреты назад не показываются (только «задан / нет»). В форме запуска токен и UA можно разово
переопределить (как `--token/--no-token`, `--ua`).

- **Дашборд** — метрики по запускам во времени (проверки, доступность, ошибки, TTFB p95, пробы по видам, зависимость от рендеринга),
  дельта к прошлому запуску, «Свой график» из любых метрик. Считается из `runs/pages/probes/diffs/check_results`, так что совпадает с отчётами.
- **Проверки** — матрица «проверка × запуск», что ухудшилось/исправилось с прошлого запуска, детали и история.
- **Справочник страниц** — URL лежат в БД (`ref_urls`): добавить, править на месте, удалить, массово сменить статус/удалить,
  поиск и фильтры, история ответов по URL. **Загрузить CSV**: предпросмотр → применение; режимы «добавить / обновить / заменить»;
  `site;type;url;note;status` или старый `type,url,note` с выбором сети; `;` `,` таб, UTF-8 и Windows-1251. «Скачать CSV» — выгрузка.
- **Сети и типы** — словари сетей, типов страниц, ответственных (тоже правка и CSV) и журнал изменений.
- **Запуски** — кнопка запуска (сбор + проверки) с логом в реальном времени, очередь, ссылки на отчёты.
- **Расписание** — ежедневно в HH:MM по дням недели или каждые N часов (локальное время машины; работает, пока запущен `web.py`).

БД — источник правды для справочника: `collect_html.py` читает URL из неё, а `registry/<сеть>.csv` пересоздаётся как зеркало
(оригиналы один раз копируются в `registry/_backup_before_db/`). При первом старте пустая БД заполняется из `справочники/*.csv` и `registry/*.csv`
(`python web.py --reseed` — дозагрузить ещё раз, существующее не меняется). Если для сети в БД нет строк, сборщик читает CSV, как раньше.
Метрики в динамике появляются по мере запусков: чем регулярнее расписание и чем одинаковее параметры (`--limit`, варианты), тем сравнимее точки.
