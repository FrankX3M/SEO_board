## Ответственные, заголовки и карты сайта

Список ответственных управляется в карточке сайта: имя, почта и область ответственности. В «Типах страниц» для выбранного сайта появилась колонка с выбором нескольких ответственных из этого списка. Отдельная вкладка «Ответственные» убрана. Старые общие назначения один раз копируются для каждого сайта с сохранением покрытия; исходный справочник не удаляется. Дальнейшие изменения и удаления действуют только внутри выбранного сайта.

Токен сайта редактируется в общей таблице HTTP-заголовков. Пустое поле сохраняет прежний секрет. Удаление снимает индивидуальный токен; общий токен, если настроен, остаётся запасным, как и раньше.

Карты сайта добавляются построчно. Строка проверяет корректность адреса, а кнопка «Проверить» отдельно запрашивает HTTP-доступность и XML-структуру sitemap с сохранёнными настройками доступа. Результат содержит время проверки; после редактирования строки он сбрасывается. Это не полная XSD-валидация и не обход вложенных карт. Общая проверка карт сохранена для диагностики robots.txt и вложенных индексов.

## Навигация интерфейса

Верхнее меню: **Обзор**, **Аудит**, **Запуски**. Общий выбор сайта сохраняется при переходах; параметр в открываемой ссылке имеет приоритет.

- **Аудит**: проверки, структура и индексация (сравнение поисковых данных со сканированием), ИИ-анализ.
- **Настройки → Страницы и источники**: контрольные URL, данные сканирования, данные поисковых систем. Загрузка поисковых выгрузок отделена от анализа; GSC показывает страницы с показами, а не полный индекс.
- **Запуски**: история, очередь, расписание. Кнопка «Запустить аудит» открывает общую форму. Редко используемые параметры находятся в раскрываемом блоке; значения по умолчанию сохранены.
- **Настройки**: сайты, интеграции, правила проверок, справочники, система, журнал изменений. Индивидуальные параметры редактируются в карточке сайта. Старые ссылки на настройки скорости перенаправляются в карточку.

Существующие адреса и обработчики сохранены. `/runs?view=new` — форма запуска, `/runs?view=queue` — задания, `/orphans?view=sources` — поисковые выгрузки. Без JavaScript настройки доступны на одной странице. Настройки не меняют прежнюю область применения и правила наследования; новые профили запуска и индивидуальные пороги сайтов не добавлены.

Ниже сохранено описание возможностей; прежние названия разделов соответствуют новой структуре выше.

## Веб-интерфейс

```
pip install -r requirements.txt
python web.py                 :: http://localhost:8765 (открывается сам; --no-open, --port, --env-file)
python -m unittest tests.test_web
```
Слушает только локальный адрес, входа нет (`--allow-remote` — на свой риск). Токены, UA, карты сайта, ключи и пороги задаются на странице «Доступ» и хранятся в БД (те же значения читают консольные скрипты); `.env` — только запасной вариант, как у остальных
скриптов; в интерфейсе секреты не показываются (страница «Доступ» говорит лишь «задан / нет»). В форме запуска токен и UA можно разово
переопределить (как `--token/--no-token`, `--ua`).

- **Дашборд** — метрики по запускам во времени (проверки, доступность, ошибки, TTFB p95, пробы по видам, зависимость от рендеринга),
  дельта к прошлому запуску, «Свой график» из любых метрик. Считается из `runs/pages/probes/diffs/check_results`, так что совпадает с отчётами.
- **Проверки** — матрица «проверка × запуск», что ухудшилось/исправилось с прошлого запуска, детали и история.
- **Справочник страниц** — URL лежат в БД (`ref_urls`): добавить, править на месте, удалить, массово сменить статус/удалить,
  поиск и фильтры, история ответов по URL. **Загрузить CSV**: предпросмотр → применение; режимы «добавить / обновить / заменить»;
  `site;type;url;note;status` или старый `type,url,note` с выбором сети; `;` `,` таб, UTF-8 и Windows-1251. «Скачать CSV» — выгрузка.
- **Сети и типы** — словари сетей, типов страниц, ответственных (тоже правка и CSV) и журнал изменений.
- **Запуски** — кнопка запуска (сбор + проверки) с логом в реальном времени, очередь, ссылки на отчёты.
- **Расписание** — ежедневно в HH:MM по дням недели или каждые N часов (локальное время машины; работает, пока запущен `web.py`).

БД — источник правды для справочника: `collect_html.py` читает URL из неё, а `registry/<сеть>.csv` пересоздаётся как зеркало
(оригиналы один раз копируются в `registry/_backup_before_db/`). При первом старте пустая БД заполняется из `справочники/*.csv` и `registry/*.csv`
(`python web.py --reseed` — дозагрузить ещё раз, существующее не меняется). Если для сети в БД нет строк, сборщик читает CSV, как раньше.
Метрики в динамике появляются по мере запусков: чем регулярнее расписание и чем одинаковее параметры (`--limit`, варианты), тем сравнимее точки.

## Версия 2: что добавлено

- **Несколько ключей.** В «Доступ → Внешние сервисы»: ключи PageSpeed списком (по одному в строке); для GSC — файлы аккаунтов (общие там же, для сети — в её карточке) и ресурсы Search Console сети (`sc-domain:5ka.ru`, `https://www.5ka.ru/`). Через `.env` то же задаётся как `PAGESPEED_API_KEYS=k1,k2,k3`, `GSC_SERVICE_ACCOUNT_FILES`, `NET_5KA_GSC_FILES`, `NET_5KA_GSC_PROPERTIES`. Ключи по кругу, исчерпанный пропускается. Квота PageSpeed — на проект Google Cloud (ключи из разных проектов), квота URL Inspection — на ресурс GSC, а не на аккаунт. Включение: галочка «Внешние сервисы» или `run_checks.py --external`. Лимиты: `GSC_MAX_URLS`, `PSI_MAX_URLS`, `CWV_LCP_MS`, `CWV_CLS`, `CWV_TBT_MS`, кеш `EXT_CACHE_HOURS`.
- **Краулы Screaming Frog.** Раздел «Краул»: загрузка CSV «Internal → All» по сети (или `python import_crawl.py --network 5ka файл.csv`), сравнение выгрузок, просмотр с фильтрами. Каждый краул — точка ◆ на дашборде; проверки про 4xx/5xx, ссылки на 404/редиректы, сирот, canonical и карту сайта считаются по всему краулу. Лимит файла `CRAWL_MAX_MB`.
- **Сироты: индекс против краула.** Раздел «Сироты»: выгрузка страниц в поиске из Яндекс Вебмастера (API, до 50 000 URL) и страниц с показами из Google Search Console (API) или из файла CSV/XLSX; сравнение с краулом Screaming Frog: нет в краулe, нет входящих ссылок, глубже MAX_DEPTH, не 200, расхождение сигналов; живая проверка «сирот» (200 или уже 404/редирект), экспорт CSV/Excel. Консоль: `python find_orphans.py --help`. Проверка `index_orphans` попадает в отчёты.
- **Дашборд** разбит на блоки чек-листа; слева сеть, период и дерево метрик (выбор запоминается в браузере).
- **Проверки** — аккордеон по блокам; в каждой «Как проверить»: запросы, UA, токен да/нет, статус, цепочка, curl с `$SP_TOKEN`.
- **Debug** (галочка при запуске или `--debug`): сохраняет строки UA и пороги проверок.
- **Выгрузка**: отчёт HTML для отправки, XLSX чек-листа, CSV проверок и метрик.
- **ИИ**: страница «ИИ» объясняет, что и куда уходит; запуск после проверок или кнопкой для готового запуска (`--ai-only`). Статусы ИИ не меняет.


## Детализация скорости страниц

В блоке «Скорость загрузки» таблица показывает каждый URL и тип страницы отдельно для mobile и desktop: Performance, LCP, CLS, TBT, FCP Lighthouse и LCP/INP/CLS CrUX. Для каждой полевой метрики указан источник: конкретная страница или сайт (origin). При отсутствии CrUX лабораторные значения не подставляются в полевые колонки. CLS CrUX приводится к коэффициенту. Статус проверки рассчитывается по лабораторным LCP/CLS/TBT; полевые значения показываются отдельно.

Доступны поиск по URL, фильтр устройства, история за выбранный период и график лабораторной метрики выбранной страницы. Дата относится к самому замеру; повторное чтение кеша не создаёт новую точку графика. Подробная история сохраняется при новых проверках, старые текстовые результаты не преобразуются в метрики. Для сбора включите «Внешние сервисы», для регулярного обновления настройте «Расписание». Набор страниц задаётся отдельно для каждой сети: «Доступ → Сети → Страницы для проверки скорости». По умолчанию проверяются все активные URL главной, каталогов, категорий и товаров из справочника; можно выбрать свои типы и добавить конкретные адреса. Лимит сбора HTML на этот набор не влияет. Все выбранные URL проверяются на mobile и desktop, дубли удаляются. PSI_MAX_URLS ограничивает только отдельную проверку мобилопригодности. После обновления старый формат кеша PageSpeed обновится новым запросом.
# Карточки сайтов и HTTP-заголовки

В разделе «Сети и типы → Сети» у каждого сайта есть карточка «Настройки, типы и журналы». В ней собраны адрес, токен, карты сайта, Search Console, страницы для проверки скорости, типы и URL страниц, последние запуски и ссылки на их журналы. Типы остаются общим справочником; в карточке показаны типы, используемые URL этого сайта.

В настройках сайта раздел «HTTP-заголовки» позволяет добавлять произвольные пары имя/значение, выключать и удалять строки. Например, для выбора версии сайта: имя `Cookie`, значение `site_version=new`. Заголовки применяются к обычным HTTP-запросам и браузерным проверкам только своего сайта и его поддоменов; пользовательский заголовок заменяет одноимённый стандартный заголовок или заголовок токена. В браузере Cookie также устанавливается в хранилище cookies до открытия страницы. После сохранения значения скрыты; пустое поле сохраняет прежнее значение, удаление строки удаляет заголовок. Журнал изменений не содержит значений заголовков.
